Нужно выполнить UI/UX-редизайн календаря ППР в ветке feature/ppr проекта unaittasks.

Важно:
- НЕ менять бизнес-логику календаря
- НЕ ломать текущие правила переноса
- НЕ менять архитектуру данных, scheduler, materialization и read-model, если это не требуется строго для UI
- Основная задача: улучшить читаемость, визуальную иерархию и удобство ежедневной работы инженера

========================
КОНТЕКСТ
========================

Сейчас календарь ППР уже реализован логически правильно:
- есть 3 уровня:
  1. годовой обзор по группам систем
  2. обзор по системам внутри выбранной группы
  3. месячный operational-календарь по дням
- есть агрегаты по месяцам
- есть перенос работ
- есть разделение на перенос до materialization и после materialization

Проблема сейчас уже не в логике, а в UI/UX:
- интерфейс перегружен текстом
- слишком слабая визуальная иерархия
- day-grid месяца тяжело читать
- много повторяющихся действий
- верхние уровни выглядят слишком таблично и шумно
- месячный экран больше похож на dev-экран, чем на удобный рабочий инструмент инженера

========================
ЧТО НУЖНО ПОЛУЧИТЬ
========================

Нужно предложить и затем реализовать редизайн календаря ППР так, чтобы:

1. Годовые уровни читались как обзор нагрузки, а не как перегруженные таблицы
2. Месячный календарь стал удобным operational-экраном
3. Стало легче визуально находить перегруженные дни
4. Стало меньше визуального шума
5. Действия были более аккуратно встроены в интерфейс
6. Дизайн остался совместим с PWA и использованием на ноутбуке/планшете
7. По возможности сохранить текущую темную стилистику проекта, но сделать ее чище и современнее

========================
ОБЩИЕ ПРИНЦИПЫ РЕДИЗАЙНА
========================

Нужно придерживаться таких принципов:

- меньше текста на экране одновременно
- сильнее визуальная иерархия
- сначала обзор, потом детали
- важное должно считываться за 1-2 секунды
- вторичная информация должна быть приглушена
- повторяющиеся действия не должны шуметь
- интерфейс должен помогать перераспределять нагрузку, а не просто показывать данные

========================
ТРЕБОВАНИЯ К УРОВНЮ 1 И 2
========================

Уровень 1:
- годовой обзор по группам систем
- строки: группы систем
- колонки: месяцы
- в ячейках: только главные метрики
  - количество позиций
  - суммарные нормо-часы
- убрать лишние длинные подписи внутри ячеек
- сделать ячейки визуально компактными и легко сравнимыми между собой
- добавить понятную визуальную систему акцентов:
  - норма
  - перегруз
  - carryover
  - просрочка
- желательно использовать:
  - число как основную метрику
  - маленький badge/pill для часов
  - tooltip/popover для деталей вместо постоянного текста

Уровень 2:
- обзор по системам внутри выбранной группы
- визуально должен быть максимально согласован с уровнем 1
- пользователь должен чувствовать, что он просто провалился глубже, а не попал на другой экран
- те же принципы компактности и метрик

Нужно улучшить:
- читаемость таблиц
- отступы
- контраст заголовков
- hover/focus states
- визуальную кликабельность drill-down

========================
ТРЕБОВАНИЯ К УРОВНЮ 3
========================

Уровень 3 — месячный календарь по дням — самый важный экран.

Сейчас проблема:
- карточки в дне слишком длинные
- слишком много текста
- повторяется кнопка "Перенести"
- тяжело быстро понять загруженность дня

Нужно сделать day-grid месяца более диспетчерским.

Требования:

1. В шапке каждого дня показывать:
- номер дня
- количество работ за день
- суммарные нормо-часы за день

2. Визуально различать дни по нагрузке:
- пустой день
- легкий день
- нормальный день
- перегруженный день
Это можно сделать через:
- оттенок фона
- индикатор в шапке ячейки
- акцент по сумме часов

3. Карточки работ внутри дня сделать компактнее.
В карточке показывать только:
- краткое название оборудования
- краткое название работы/шаблона
- нормо-часы
- статус

Не нужно держать на карточке слишком много текста одновременно.

4. Постоянную кнопку "Перенести" на каждой карточке желательно убрать из постоянного вида.
Вместо этого продумать один из вариантов:
- кнопка появляется по hover/focus
- действие уходит в dropdown / menu
- клик по карточке открывает side panel / drawer с деталями и действиями
- допустим другой аккуратный вариант, если он реально улучшает UX

5. Нужна возможность удобного чтения месяца при большом количестве работ.
Можно рассмотреть:
- compact mode / detailed mode
- ограничение высоты карточки
- более компактную типографику
- better spacing
- раскрытие деталей по клику

6. Нужно сохранить текущую функциональность:
- видимость статуса
- перенос
- различие между plan item и materialized task, если это уже отражено в UI

========================
ВЕРХНЯЯ ПАНЕЛЬ / ФИЛЬТРЫ
========================

Нужно переработать верхнюю панель:
- сделать ее компактнее
- улучшить визуальную структуру
- сгруппировать:
  - контекст
  - фильтры
  - действия

Желательно:
- хороший заголовок и подзаголовок
- более аккуратная компоновка фильтров
- кнопки показать/сбросить/сформировать месяц сделать более логичными по иерархии
- по возможности сделать панель удобной для скролла и повторного использования

========================
ЦВЕТОВАЯ СИСТЕМА
========================

Нужно привести цвета к понятной и единообразной системе.

Желательно, чтобы:
- синий = план / обычное состояние
- желтый = внимание / carryover
- красный = просрочка / перегруз / критично
- зеленый = закрыто / успешно
- фиолетовый или другой отдельный цвет = materialized / особый статус, если нужно

Важно:
- цвет должен не украшать, а передавать смысл
- одно и то же цветовое значение должно одинаково читаться на всех уровнях календаря

========================
ТИПОГРАФИКА И ПЛОТНОСТЬ
========================

Нужно улучшить:
- контраст между главным и вторичным текстом
- размеры текста
- межстрочные интервалы
- отступы внутри карточек и ячеек

Цель:
- меньше ощущения "простыни"
- больше ощущения "рабочего инструмента"

Нужно, чтобы:
- главная информация выделялась сразу
- вторичная не спорила с ней
- экран не разваливался на десятки равносильных элементов

========================
ОСОБЫЙ АКЦЕНТ
========================

Нужно сделать интерфейс таким, чтобы инженер мог:
- быстро понять нагрузку по году
- быстро провалиться до нужной системы
- быстро увидеть перегруженные дни месяца
- удобно перераспределять работы
- не тонуть в избыточном тексте и повторяющихся кнопках

То есть итоговый календарь должен выглядеть не как dev-table, а как аккуратный рабочий диспетчерский интерфейс.
